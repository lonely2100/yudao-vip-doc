          【模型接入】智谱 GLM

          项目基于 Spring AI + 自己实现的 models/zhipu，实现 智谱 GLM (opens new window) 的接入，底层复用兼容 OpenAI 协议的客户端：

          功能 模型 Spring AI 客户端
          AI 对话 GLM-5.3、GLM-5.3-Flash、GLM-5.2 等 ZhiPuChatModel
          AI 绘画 CogView (opens new window) 暂未接入

          # 1. 申请密钥

          智谱 AI 有开源模型，可以私有化部署。

          不过它最新、最强的模型通常没有开源，所以只能通过官方的 API 服务接入。

          # 1.1 申请智谱 AI 密钥

          ① 在 智谱 AI 开放平台 (opens new window) 上，注册一个账号。目前，默认注册就送 2500w tokens，还是蛮爽的。

          ② 在 API keys (opens new window) 菜单，复制系统默认 API key 即可。

          申请完成后，可以在我们系统的 [AI 大模型 -> 控制台 -> API 密钥] 菜单，进行密钥的配置。只需要填写“密钥”，不需要填写“自定义 API URL”（因为 Spring AI 默认官方地址）。如下图所示：

          友情提示：

          目前 ai_model 表中，已经预置了一些模型，可以直接使用！！！

          # 2.1 AI 对话

          使用 《AI 对话》 时，需要在 [AI 大模型 -> 控制台 -> 模型配置] 菜单，配置对应的聊天模型，并选择前面配置的智谱 API 密钥。

          不同模型的最大输出 Tokens 不同，填写模型配置的 maxTokens 时可以参考下表：

          模型标识 最大输出 Tokens
          glm-5.3 131072
          glm-5.3-flash 131072
          glm-5.2 131072
          glm-5.1 131072
          glm-5 131072
          glm-5-turbo 131072

          glm-5.3、glm-5.3-flash 的 thinking.type 仅支持 enabled，不能关闭思考。glm-5.3 仅支持文本输入，见 GLM-5.3 (opens new window) 文档；glm-5.3-flash 官方支持图片、视频输入，在 [AI 大模型 -> 控制台 -> 模型配置] 中给模型勾选「图片」输入能力后，AI 对话会把图片作为多模态参数（UserMessage 的 Media）传递；但该平台复用 Spring AI 的 DeepSeekChatModel，实测它在 Spring AI 1.1.8 / 2.0.0 / 2.0.1 中仍会丢弃图片，是否支持以项目实际采用的 Spring AI 版本为准。未勾选时，图片仍按原附件逻辑以 Base64 文本拼接，只修改模型标识不能实现图片理解。详见 GLM-5.3-Flash (opens new window) 文档。

          # 3. 如何使用？

          ① 如果你的项目里需要直接通过 @Resource 注入 ZhiPuChatModel 等对象，需要把 application.yaml 配置文件里的 yudao.ai.zhipu 配置项，替换成你的！

          yudao:
  ai:
    zhipu: # 智谱 AI（GLM）
      enable: true
      api-key: ${ZHIPU_API_KEY}
      model: glm-5.3-flash

          ② 如果你希望使用 [AI 大模型 -> 控制台 -> API 密钥] 菜单的密钥配置，则可以通过 AiModelService 的 #getChatModel(...) 方法，获取对应的模型对象。

          ① 和 ② 这两者的后续使用，就是标准的 Spring AI 客户端的使用，调用对应的方法即可。

          另外，ZhiPuAiChatModelTests 里有对应的测试用例，可以参考。
