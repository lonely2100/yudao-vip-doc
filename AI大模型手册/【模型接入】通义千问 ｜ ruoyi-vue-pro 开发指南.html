          【模型接入】通义千问

          项目基于 Spring Alibaba AI 的 spring-cloud-alibaba-starters (opens new window)，实现 通义千问 (opens new window) 的接入：

          功能 模型 Spring AI 客户端
          AI 对话 通义千问 (opens new window) DashScopeChatModel (opens new window)（master-jdk17）、TongYiChatModel（master-jdk25，OpenAI 兼容接口）
          AI 绘画 通义万象 (opens new window) DashScopeImageModel (opens new window)

          # 1. 申请密钥

          通义千问有开源版本 (opens new window)，提供包括 0.6B、1.7B、4B、8B、14B、32B 等稠密模型，以及 30B-A3B、235B-A22B、480B-A35B 等 MoE/代码模型，所以我们可以私有化部署。

          当然，能力更强的模型，就需要使用阿里云提供的大模型服务 (opens new window)。

          下面，我们来看看这两种方式怎么申请（部署）？

          友情提示：

          一般情况下，建议先采用“方式一：申请阿里云密钥”，因为阿里云提供了一定的免费额度，具体可以看 阿里云计费管理（需要登录） (opens new window)，搜“免费额度”或者“限时免费”关键字。

          # 1.1 方式一：申请阿里云密钥

          参考 《阿里云大模型 —— 快速模型》 (opens new window) 文档，重点是“开通 DashScope 并创建 API-KEY (opens new window)”部分，其它都不用关注。一般 1-2 分钟就可以申请完成！

          申请完成后，可以在我们系统的 [AI 大模型 -> 控制台 -> API 密钥] 菜单，进行密钥的配置。只需要填写“密钥”，不需要填写“自定义 API URL”（因为 Spring AI 默认官方地址）。如下图所示：

          # 1.2 方式二：私有化部署

          ① 访问 https://ollama.ai/download (opens new window)，下载对应系统 Ollama 客户端，然后安装。

          ② 安装完成后，在命令中执行 ollama run qwen2.5 命令，一键部署 通义千问开源模型 (opens new window)，默认跑的是 qwen:7b 模型。

          部署完成后，可以在我们系统的 [AI 大模型 -> 控制台 -> API 密钥] 菜单，进行密钥的配置。需要填写“密钥” + “自定义 API URL”（因为让 Spring AI 使用该地址）。如下图所示：

          # 2. 模型配置

          友情提示：

          目前 ai_model 表中，已经预置了一些模型，可以直接使用！！！

          # 2.1 AI 对话

          使用 《AI 对话》 时，需要在 [AI 大模型 -> 控制台 -> 模型配置] 菜单，配置对应的聊天模型。

          模型有：qwen3.8-max、qwen3.8-flash、qwen3.7-max、qwen3.7-plus 等等，可通过 阿里云计费管理（需要登录） (opens new window) 查看。

          不同模型的最大输出 Tokens 不同，填写模型配置的 maxTokens 时可以参考下表：

          模型标识 最大输出 Tokens
          qwen3.8-max 131072
          qwen3.8-flash 131072
          qwen3.7-max 65536
          qwen3.7-plus 65536

          qwen3.8-max、qwen3.8-flash 官方支持图片、视频输入，见 qwen3.8-max (opens new window) 和 qwen3.8-flash (opens new window) 文档。在 [AI 大模型 -> 控制台 -> 模型配置] 中给模型勾选「图片」输入能力后，AI 对话会把图片作为多模态参数（UserMessage 的 Media）传递：master-jdk17 分支使用 DashScopeChatModel，本轮带图片时自动开启通义的多模态接口（multiModel），不再只依赖 AiChatUtils.TONG_YI_MULTI_MODELS 名单；master-jdk25 分支由于 Spring AI Alibaba 2.0.0-M1.1 与 Spring AI 2.0.x 不兼容，通义对话改为通过阿里云百炼的 OpenAI 兼容接口调用，图片按 OpenAI 消息格式传递，无需切换接口。未勾选时，图片仍按原附件逻辑以 Base64 文本拼接，只修改模型标识不能实现图片理解。视频附件暂未按多模态参数传递。

          # 2.2 AI 绘图

          使用 《AI 绘图》 时，需要在 [AI 大模型 -> 控制台 -> 模型配置] 菜单，配置对应的图像模型。

          模型有：wanx-v1、wanx-sketch-to-image-v1 等等。

          阿里云百炼当前的文生图模型有 qwen-image-3.0-pro、wan2.7-image-pro 等，见 文生图 (opens new window) 和 万相图像生成与编辑 API (opens new window) 文档。项目使用的 Spring AI Alibaba DashScopeImageApi（1.1.2.2 / 2.0.0-M1.1）按模型名选择接口：qwen-image 前缀的模型走 multimodal-generation 接口；万相只精确识别 wan2.6-image，wan2.7-image-pro 会落到旧的 text2image 接口，需要适配后才能使用。以上只是源码中的路由，这些新模型均未在项目中实测。

          注意，如果生成图片报错时，可以看看是不是图片尺寸不对，例如说它可能只支持 1024x1024、1024x768、768x1024、768x1152 等尺寸，可见 https://t.zsxq.com/gNRTG (opens new window) 或 https://t.zsxq.com/1aUhJ (opens new window) 帖子。

          # 3. 如何使用？

          ① 如果你的项目里需要直接通过 @Resource 注入 TongYiChatModel、TongYiImageModel 等对象，需要把 application.yaml 配置文件里的 spring.ai.dashscope. 配置项，替换成你的！

          ps：暂时不支持“方式二：私有化部署”。（后续会支持！）

          spring:
  ai:
    dashscope: # 通义千问
      api-key: ${DASHSCOPE_API_KEY}

          ② 如果你希望使用 [AI 大模型 -> 控制台 -> API 密钥] 菜单的密钥配置，则可以通过 AiModelService 的 #getChatModel(...) 或 #getImageModel(...) 方法，获取对应的模型对象。

          ① 和 ② 这两者的后续使用，就是标准的 Spring AI 客户端的使用，调用对应的方法即可。

          另外，TongYiChatModelTests、TongYiImagesModelTest 里有对应的测试用例，可以参考。
