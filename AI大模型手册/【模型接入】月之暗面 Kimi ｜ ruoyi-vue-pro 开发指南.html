          【模型接入】月之暗面 Kimi

          项目基于 Spring AI + 自己实现的 models/moonshot，实现 Moonshot (opens new window) 的接入，底层复用兼容 OpenAI 协议的客户端：

          功能 模型 Spring AI 客户端
          AI 对话 kimi-k3.1-pro、kimi-k2.7-code、kimi-k2.6 等 MoonshotChatModel
          AI 绘画 不支持 暂未接入

          # 1. 申请密钥

          Moonshot 有开源模型，可以私有化部署。

          不过官方 API 服务使用也比较方便，可以去官网申请 API Key，然后通过项目接入。

          # 1.1 方式一：申请 Moonshot 密钥

          ① 在 Moonshot (opens new window) 上，注册一个账号。

          ② 在 Moonshot 开放平台 -> API Key 管理 (opens new window) 上，创建一个 API Key 密钥。

          申请完成后，可以在我们系统的 [AI 大模型 -> 控制台 -> API 密钥] 菜单，进行密钥的配置。只需要填写“密钥”，不需要填写“自定义 API URL”（因为 Spring AI 默认官方地址）。如下图所示：

          # 2.1 AI 对话

          使用 《AI 对话》 时，需要在 [AI 大模型 -> 控制台 -> 模型配置] 菜单，配置对应的聊天模型，并选择前面配置的 Moonshot API 密钥。

          不同模型的最大输出 Tokens 不同，填写模型配置的 maxTokens 时可以参考下表：

          模型标识 最大输出 Tokens
          kimi-k3.1-pro 1048576
          kimi-k2.7-code 16384
          kimi-k2.6 262144

          kimi-k3.1-pro 的最大输出来自官方 max_completion_tokens 参数（默认 131072），不是上下文窗口；项目以 max_tokens 字段发送，以当前 API 校验为准。它始终开启思考，不接受 thinking 参数（包括 {"type": "disabled"}），推理强度由顶层 reasoning_effort 控制；temperature 固定为 1。详见 Chat Completions API (opens new window) 文档。

          Kimi 官方视觉输入不支持公网图片 URL，只接受 Base64 或 ms://<file-id>，见 配置 Kimi 视觉模型 (opens new window)。在 [AI 大模型 -> 控制台 -> 模型配置] 中给模型勾选「图片」输入能力后，AI 对话会把图片作为多模态参数（UserMessage 的 Media）传递；但该平台复用 Spring AI 的 DeepSeekChatModel，实测它在 Spring AI 1.1.8 / 2.0.0 / 2.0.1 中仍会丢弃图片，是否支持以项目实际采用的 Spring AI 版本为准。未勾选时，图片仍按原附件逻辑以 Base64 文本拼接，只修改模型标识不能实现图片理解。

          # 3. 如何使用？

          ① 如果你的项目里需要直接通过 @Resource 注入 MoonshotChatModel 等对象，需要把 application.yaml 配置文件里的 yudao.ai.moonshot 配置项，替换成你的！

          yudao:
  ai:
    moonshot: # 月之暗面（KIMI）
      enable: true
      api-key: ${MOONSHOT_API_KEY}
      model: kimi-k3.1-pro

          ② 如果你希望使用 [AI 大模型 -> 控制台 -> API 密钥] 菜单的密钥配置，则可以通过 AiModelService 的 #getChatModel(...) 方法，获取对应的模型对象。

          ① 和 ② 这两者的后续使用，就是标准的 Spring AI 客户端的使用，调用对应的方法即可。

          另外，MoonshotChatModelTests 里有对应的测试用例，可以参考。
