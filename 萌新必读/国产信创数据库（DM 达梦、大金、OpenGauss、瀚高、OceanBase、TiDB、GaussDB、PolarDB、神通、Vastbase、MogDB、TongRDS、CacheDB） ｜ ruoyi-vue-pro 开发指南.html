          # 1. DM 达梦数据库

          # 1.1 如何安装？

          可以使用 Windows 或 Docker 等多种方式。

          注意，建议从 达梦官网 (opens new window) 下载较新的 DM8 服务端安装包或官方 Docker 镜像，不推荐使用年代久远的第三方镜像。“DM8”或 Docker 镜像的标签不能代表实际版本，需要以下面 SQL 查询到的完整服务端版本为准。

          如何确认达梦的版本？

          使用应用连接数据库的同一账号，连接应用实际使用的数据库，执行如下只读 SQL：

          -- ① 查询服务端的完整版本
SELECT * FROM v$version;
-- ② 检查 FIND_IN_SET 函数是否可用，应返回 2
SELECT FIND_IN_SET('b', 'a,b,c') FROM DUAL;

          达梦 官方现行手册 (opens new window) 中列出了 FIND_IN_SET 函数，项目的部分查询会用到它。如果第 ② 条 SQL 提示函数无法识别，优先评估升级达梦服务端，升级后再复测；只升级 JDBC 驱动，无法为服务端补充函数。

          本地验证使用的是 DM 服务端 8.1.3.162、JDBC 驱动 8.1.3.140，第 ② 条 SQL 返回 2。这只是本地验证的示例，不是官方要求的最低版本，也不代表当前最新版本。

          # 4. HighGo 瀚高数据库

          # 4.1 如何安装？

          可以使用 Linux 或 Docker 等多种方式。

          注意，目前项目按照 PostgreSQL 兼容模式适配瀚高数据库，并在瀚高企业版 6.0.4 上完成了组件级验证（见《4.4.5 验证范围？》）。

          # 4.1.1 Docker 方式

          ① 下载瀚高官方 Docker 镜像，并加载镜像文件。加载后，将镜像打成本地标签：

          docker load -i <highgo-image>.tar
docker tag <image>:<tag> highgo:local

          ② 在项目 sql/tools 目录下运行：

          docker compose up -d highgo

          注意：highgo 服务属于 highgo profile，执行 docker compose up -d 时不会启动，需要像上面一样指定服务名。不同瀚高镜像的数据目录可能不同，如果容器无法启动，请按镜像实际 PGDATA 修改 docker-compose.yaml 中的 highgo 数据卷挂载目录。

          # 4.2 如何导入数据？

          有手动导入、Docker 一键导入两种方式，任选其一即可，不要混用。下面先介绍手动导入，适用于任意方式安装的瀚高数据库：

          ① 使用 DataGrip、DBeaver 等数据库工具，选择 PostgreSQL 数据库类型，连接瀚高数据库。默认端口为 5866，账号、密码以安装时设置或镜像说明为准。

          注意，如果数据库开启了 SM3 等 PostgreSQL 驱动不支持的认证方式，选择 PostgreSQL 类型会连接失败，需要在工具中配置瀚高的 JDBC 驱动后再连接。

          ② 创建一个名字为 ruoyi-vue-pro 的数据库（名字带 -，SQL 中需要写成 CREATE DATABASE "ruoyi-vue-pro";），在该数据库中先执行项目中的 sql/highgo/quartz.sql 文件，再执行 sql/highgo/ruoyi-vue-pro.sql 文件。

          友情提示：如果使用 Docker，也可以直接导入（无需执行上述手动步骤）：

          在项目 sql/tools 目录下运行，使用 postgres:14.2 镜像中的 psql 客户端，创建 ruoyi-vue-pro 数据库并导入上述 SQL 文件：

          HIGHGO_PASSWORD='数据库密码' docker compose run --rm highgo-init

          默认使用瀚高的 highgo 账号连接 highgo 数据库执行建库，可以通过 HIGHGO_USER、HIGHGO_MAINTENANCE_DB 环境变量修改；密码以镜像或安装时的实际设置为准，脚本不会修改数据库的认证配置。

          注意，导入脚本只允许创建全新的数据库，数据库已存在（包括空库）或重复执行时，会拒绝导入并返回失败；导入失败时会保留数据库，便于排查。该方式只适用于 PostgreSQL 客户端支持的认证方式（例如说 md5、scram-sha-256），数据库开启 SM3 等专有认证时，请使用瀚高客户端按上述步骤手动导入。

          友情提示

          瀚高数据库兼容 PostgreSQL，所以项目 SQL、Quartz、Flowable 都按照 PostgreSQL 兼容模式处理。

          # 4.3 如何启动项目？

          ① 在 yudao-server/pom.xml 中引入 PostgreSQL JDBC 驱动，版本由 Spring Boot 统一管理，无需填写（使用瀚高 JDBC 驱动时，见《4.4.4 使用瀚高 JDBC 驱动？》）：

          <dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
</dependency>

          注意：只在 `yudao-dependencies` 中声明，是无法引入驱动的！

          yudao-dependencies 是 Maven BOM，<dependencyManagement> 只统一依赖的版本，不会把 jar 包引入到项目中。yudao-spring-boot-starter-mybatis 中的 postgresql 依赖也是 <optional>true</optional>，不会传递到 yudao-server。所以，需要在最终运行的 yudao-server 模块的 <dependencies> 中引入。

          打包后，可以执行 unzip -l yudao-server/target/yudao-server.jar | grep postgresql，确认 BOOT-INF/lib 中包含驱动。

          ② 修改 application-local.yaml 配置文件，将数据库的 url、username、password 修改为瀚高数据库。例如说：

          spring:
  datasource:
    dynamic:
      druid:
        validation-query: SELECT 1
      datasource:
        master:
          url: jdbc:postgresql://127.0.0.1:5866/ruoyi-vue-pro
          driver-class-name: org.postgresql.Driver
          username: highgo
          password: ${HIGHGO_PASSWORD}

          注意，如果本地配置里 validation-query 仍然是 SELECT 1 FROM DUAL，需要改成 SELECT 1，否则 PostgreSQL/瀚高会因为不存在 DUAL 表导致连接校验失败。

          username、password 需要填写数据库实际的账号和密码，以安装时设置或镜像说明为准。上面使用的是瀚高默认的 highgo 账号，密码通过 HIGHGO_PASSWORD 环境变量设置。

          疑问：为什么 jdbc 使用 postgres 数据库连接？

          因为瀚高数据库兼容 PostgreSQL，所以 JDBC 驱动使用的是 org.postgresql.Driver。项目会根据 url 将数据库识别为 PostgreSQL，自动使用 INPUT 主键（配合 SQL 脚本中的序列），并将 Quartz 设置为 PostgreSQLDelegate。这样，后续和 Quartz 定时任务、Flowable 工作流等等，都是可以兼容的。

          ③ 后续启动项目，就可以了。

          # 4.4.3 启动报找不到 Driver？

          启动时报 SQLException，提示找不到 org.postgresql.Driver、com.highgo.jdbc.Driver 等驱动类，说明最终运行的 yudao-server 没有引入对应的 JDBC 驱动。

          常见原因是：只在 yudao-dependencies 的 <dependencyManagement> 中声明了驱动依赖。它只管理版本，不会引入 jar 包。按照《4.3 如何启动项目？》的步骤，在 yudao-server/pom.xml 的 <dependencies> 中引入，并刷新 Maven 依赖后重新启动。

          # 4.4.4 使用瀚高 JDBC 驱动？

          瀚高 官方 JDBC 文档 (opens new window) 中的驱动类为 com.highgo.jdbc.Driver，url 格式为 jdbc:highgo://ip:端口号/数据库名，驱动需要和数据库版本、JDK 版本匹配。

          一般使用 PostgreSQL 驱动即可。如果数据库开启了 SM3（国密）等 PostgreSQL 驱动不支持的认证方式，或者需要使用瀚高驱动的专有能力，则使用与数据库版本匹配的瀚高驱动：

          ① 在 yudao-server/pom.xml 中引入瀚高驱动 com.highgo:HgdbJdbc，版本按数据库版本及厂商说明选择：

          <dependency>
    <groupId>com.highgo</groupId>
    <artifactId>HgdbJdbc</artifactId>
    <version>与数据库匹配的版本</version>
</dependency>

          ② 修改数据源配置，url 与 driver-class-name 需要配对：

          spring:
  datasource:
    dynamic:
      druid:
        validation-query: SELECT 1
      datasource:
        master:
          url: jdbc:highgo://127.0.0.1:5866/ruoyi-vue-pro
          driver-class-name: com.highgo.jdbc.Driver
          username: highgo
          password: ${HIGHGO_PASSWORD}

          项目会将 jdbc:highgo: 的 url 也识别为 PostgreSQL，与 PostgreSQL 驱动一样，自动使用 INPUT 主键和 Quartz 的 PostgreSQLDelegate，无需额外配置。

          注意，目前只有 master-jdk17 分支包含该识别处理，其它分支请使用 PostgreSQL 驱动。

          # 4.4.5 验证范围？

          在瀚高企业版 6.0.4 的试用镜像上，分别使用 PostgreSQL 驱动和瀚高驱动 6.2.2，完成了组件级验证：sql/highgo 中的项目 SQL 和 Quartz SQL 原样导入，JDBC 元数据识别、序列主键、MyBatis Plus 增删改查与分页，代码生成读取表和字段注释，Quartz 持久化任务执行，Flowable 建表、审批与定时器。

          注意，验证使用的是第三方打包的试用镜像，不是瀚高官方发布的镜像，正式环境请通过瀚高官方渠道获取安装介质和授权。这是组件级验证，不是完整项目的启动验收，也没有覆盖 SM3 等专有认证方式。如果用于正式环境，请按你使用的功能完整回归。

          # 6.4.3 事务与兼容边界？

          TiDB 兼容 MySQL 协议，但并不等同于 MySQL，使用前需要注意以下差异，详细说明见 《与 MySQL 兼容性对比》 (opens new window)：

          • 不支持存储过程、函数、触发器、事件，以及 SKIP LOCKED、XA 语法、FULLTEXT 全文索引、SPATIAL 空间类型等。如果你自己扩展的业务使用了这些特性，需要改写。
          • 默认使用悲观事务，REPEATABLE-READ 隔离级别实际为快照隔离，并且不支持间隙锁（GAP Lock）。依赖间隙锁防止并发插入的逻辑，需要改为使用唯一索引等方式保证。
          • AUTO_INCREMENT 自增编号只保证唯一，在单个 TiDB 节点内递增，但不保证连续：每个 TiDB 节点默认批量缓存 30000 个编号，重启后可能跳号。项目没有把自增主键改为 AUTO_RANDOM，编号的含义保持不变；部署多个 TiDB 节点、需要全局递增时，可参考 《AUTO_INCREMENT》 (opens new window) 的 MySQL 兼容模式。
          • 不支持 XA 语法，所以不能使用依赖 XA 的分布式事务模式。项目默认不启用 Seata、ShardingSphere，接入 TiDB 也不会自动开启它们。
          • 目前在真实的 TiDB v8.5.8（PD、TiKV、TiDB）集群上，完成了组件级验证：项目初始化 SQL 和 Quartz SQL 导入，JDBC 元数据识别、自增主键、事务回滚，MyBatis Plus 增删改查与分页，代码生成读取表和字段注释，Quartz 定时任务执行，Flowable 建表、审批、异步任务与定时器。这是组件级验证，不是完整后端应用的启动验收，没有覆盖全部业务模块。如果用于正式环境，请按你使用的模块完整回归。

          ① 访问华为云 GaussDB 下载页 (opens new window)，下载对应操作系统、CPU 架构的开发者版安装包，以及 JDBC 驱动包。开发者版的官方声明是：仅供个人学习、适配验证或测试，不得用于商业用途，也不提供高可用、升级能力。正式环境请通过华为官方渠道获取商用版本。

          # 7.2 如何导入数据？

          GaussDB 默认创建的是 A（Oracle）兼容模式的数据库，项目脚本需要使用 PG 兼容模式、UTF8 编码的数据库。

          同时，GaussDB 已经内置了 dual 视图（sys.dual、pg_catalog.dual），sql/opengauss/ruoyi-vue-pro.sql 开头的 DROP TABLE IF EXISTS dual 会报 "dual" is not a table 错误。导入时需要跳过创建 dual 表的一段，不要删除或修改内置的 dual 视图，其余 SQL 保持不变。

          有脚本导入、手动导入两种方式，任选其一即可，不要混用。

          ① 脚本导入：在安装了 GaussDB gsql 客户端的机器上（例如说以数据库安装用户登录 GaussDB 服务器，并复制项目的 sql 目录），在项目 sql/tools 目录下执行：

          GAUSSDB_PORT='数据库端口' GAUSSDB_USER='数据库账号' GAUSSDB_PASSWORD='数据库密码' bash gaussdb/create_schema.sh

          脚本会创建 PG 兼容模式（DBCOMPATIBILITY = 'PG'）、UTF8 编码的 ruoyi-vue-pro 数据库，先导入 sql/opengauss/quartz.sql，再导入跳过 dual 段的 sql/opengauss/ruoyi-vue-pro.sql。GAUSSDB_HOST 为空时，使用本机 Unix Socket 连接。

          注意，脚本只允许创建全新的数据库，数据库已存在（包括空库）或重复执行时，会拒绝导入并返回失败；dual 段的格式与预期不一致、或者没有检测到 GaussDB 内置的 dual 视图时，也会拒绝导入。导入失败时会保留数据库，便于排查。

          ② 手动导入：使用 gsql 等工具，执行如下 SQL 创建数据库，并确认 SHOW sql_compatibility; 的结果为 PG：

          CREATE DATABASE "ruoyi-vue-pro" ENCODING 'UTF8' DBCOMPATIBILITY = 'PG';

          在该数据库中，先执行 sql/opengauss/quartz.sql 文件，再执行去掉 dual 段后的 sql/opengauss/ruoyi-vue-pro.sql 文件。去掉 dual 段，可以使用如下命令生成新文件：

          sed '/^-- Table structure for dual$/,/^-- @formatter:on$/d' sql/opengauss/ruoyi-vue-pro.sql > ruoyi-vue-pro-without-dual.sql

          # 7.3 如何启动项目？

          ① 在 yudao-server/pom.xml 中引入 GaussDB JDBC 驱动：

          <dependency>
    <groupId>com.huaweicloud.gaussdb</groupId>

</dependency>

          注意，com.huaweicloud:gaussdbjdbc 是另一个坐标，不包含 GaussDB 的驱动类，不要混淆。

          ② 修改 application-local.yaml 配置文件，将数据库的 url、username、password 修改为 GaussDB 数据库。例如说：

      datasource:
        master:

          • 在 polardbx/polardb-x 官方 all-in-one 镜像 v2.5.0（CN 5.4.21）的低内存测试环境中，导入项目 SQL 时出现内存不足、连接中断，没有完成导入。官方建议该镜像分配 12 GB 以上内存。
          • DRDS 模式的数据库在没有开启外键支持时，导入 sql/mysql/quartz.sql 会报 Do not support foreign key 错误；开启外键支持后的 DRDS、AUTO 模式，同样因为上述资源问题没有完成导入。

          所以，暂时不能认为 PolarDB-X 已经适配。如需使用，请在资源充足的环境中，按 MySQL 的方式完整回归。

          # 8.4.4 PolarDB 兼容 Oracle 是否支持？

          暂不支持。PolarDB PostgreSQL 版（兼容 Oracle）需要使用阿里云的 PolarDB 驱动（jdbc:polardb:），目前项目使用的 MyBatis Plus 版本无法识别该 url，分页等功能无法使用，也没有对应的项目 SQL。

          # 8.4.5 验证范围？

          在 PolarDB for PostgreSQL 17 的官方单机实例镜像上，使用 PostgreSQL 驱动完成了组件级验证：sql/postgresql 中的项目 SQL 和 Quartz SQL 原样导入（共 60 张表），JDBC 元数据识别、序列主键、事务回滚，MyBatis Plus 增删改查与分页，代码生成读取表和字段注释，Quartz 持久化任务执行，Flowable 建表、审批与定时器。

          注意，这是组件级验证，不是完整项目的启动验收，没有在 PolarDB 的云数据库上验证。如果用于正式环境，请按你使用的功能完整回归。

          # 9. 神通数据库

          神通数据库是天津神舟通用的国产数据库。项目支持 神通数据库 V7 的原生模式（JDBC 驱动 com.oscar.Driver，url 格式为 jdbc:oscar://ip:端口/数据库名），可以使用普通的增删改查、代码生成、Quartz 定时任务、Flowable 工作流等功能，复用 sql/opengauss 脚本，默认仍然使用 MySQL。

          # 9.1 如何安装？

          可以使用 Linux 等方式。安装介质和授权，请通过 神通官方下载中心 (opens new window) 获取，需要注册登录，并按介质中的官方说明完成安装、启动。

          注意，目前我们使用的是神通数据库 7.0.14。

          # 9.2 如何导入数据？

          ① 使用具有创建账号权限的管理员账号，执行如下 SQL，创建项目连接使用的账号。其中，yudao、数据库密码 修改为你实际使用的账号和密码：

          CREATE USER yudao WITH PASSWORD '数据库密码';

          神通会自动创建与账号同名的模式，后续使用该账号导入的表都创建在这个模式中。url 中的 currentSchema 参数不生效，所以项目连接时也要使用这个账号。

          ② 神通已经内置了 dual，且 varchar 的最大长度为 8000，所以不能直接导入 sql/opengauss/ruoyi-vue-pro.sql。在项目 sql/tools 目录下执行如下命令，生成临时脚本：只跳过创建 dual 表的一段，并将 varchar(10240) 改为 text，其余 SQL 保持不变：

          sed -e '/^-- Table structure for dual$/,/^-- @formatter:on$/d' -e 's/varchar(10240)/text/' ../opengauss/ruoyi-vue-pro.sql > /tmp/ruoyi-vue-pro-shentong.sql

          ③ 使用 yudao 账号，通过神通的客户端或其它 JDBC 工具，执行 /tmp/ruoyi-vue-pro-shentong.sql 文件。

          ④ 导入完成后，继续使用 yudao 账号执行如下 SQL，让 system_menu 的主键默认使用 system_menu_seq 序列。代码生成的菜单 SQL 插入菜单时不指定主键，需要依赖它：

          ALTER TABLE system_menu ALTER COLUMN id SET DEFAULT nextval('system_menu_seq');

          ⑤ 如需使用 Quartz 定时任务，在项目 sql/tools 目录下执行如下命令，生成 Quartz 的临时脚本：只将 bytea 字段改为神通的 BLOB（bytea 字段在神通上无法读取任务数据），其余 SQL 保持不变：

          sed 's/ bytea / BLOB /' ../opengauss/quartz.sql > /tmp/quartz-shentong.sql

          然后继续使用 yudao 账号，执行 /tmp/quartz-shentong.sql 文件。注意，该 Quartz 脚本用于全新初始化，不支持把已有数据的 bytea 字段转换为 BLOB。

          ⑥ 如需使用工作流，还需要导入 BPM 模块的 bpm_ 业务表，详见《9.4.2 Flowable 工作流？》。

          上述步骤与项目 sql/tools/README.md (opens new window) 中「神通数据库」部分一致。

          # 9.3 如何启动项目？

          ① 在 yudao-server/pom.xml 中引入神通 JDBC 驱动。项目的 yudao-dependencies、yudao-spring-boot-starter-mybatis 不包含该驱动，需要显式引入：

          <dependency>
    <groupId>com.shentongdata</groupId>
    <artifactId>oscarJDBC8</artifactId>
    <version>4.1.152</version>
</dependency>

          注意，该驱动是 Maven 中央仓库上 com.shentongdata 发布的版本，不是神通官方下载中心的配套认证版本。请使用本文列出的驱动版本：安装介质自带的 7.20 驱动实测不支持 Connection.getSchema()，代码生成会报 AbstractMethodError，不建议替换为该驱动。

          ② 修改 application-local.yaml 配置文件，将数据库的 url、username、password 修改为神通数据库。例如说：

          spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:oscar://127.0.0.1:2003/OSRDB
          driver-class-name: com.oscar.Driver
          username: yudao
          password: ${SHENTONG_PASSWORD}

          username、password 需要填写 9.2 中创建的账号和密码，端口、数据库名以安装时的设置为准。如果配置了 slave 等多个数据源，也需要同步修改对应配置。validation-query 保持默认的 SELECT 1 FROM DUAL 即可，使用的是神通内置的 dual。

          application-local.yaml 默认排除了 Quartz 的自动配置。如需使用 Quartz 定时任务，从 spring.autoconfigure.exclude 列表中删除 QuartzAutoConfiguration 这一行即可。不要通过启动参数等方式单独设置 spring.autoconfigure.exclude，它会覆盖整个排除列表，导致其它原本排除的自动配置被启用。

          疑问：项目是如何适配神通的？

          项目会识别 jdbc:oscar: 的 url，以及神通驱动返回的数据库产品名 OSCAR，自动使用 INPUT 主键，复用 MyBatis Plus 的 PostgreKeyGenerator，通过 nextval('序列名') 获取主键（配合 SQL 脚本中的序列），业务的 DO、Mapper 无需修改。MyBatis Plus 的分页，使用其对神通的内置支持；代码生成器按 Oracle、达梦的写法生成菜单 SQL。Flowable 无法识别神通的数据库产品名，项目会在未设置 flowable.database-type 时，将其按 oracle 处理。

          注意，目前只有 master-jdk17 分支包含该识别处理。

          ③ 后续启动项目，就可以了。

          # 9.4 常见问题？

          # 9.4.1 Quartz 定时任务？

          sql/opengauss/quartz.sql 使用的 bytea 字段在神通上无法读取任务数据，需要按 9.2 中第 ⑤ 步改为 BLOB 后，在全新的库中导入。

          Quartz 使用默认的 StdJDBCDelegate，不需要设置 driverDelegateClass；也不要开启 useProperties，因为任务参数包含 Long 等非字符串类型。启用方式见 9.3 中第 ② 步。

          # 9.4.2 Flowable 工作流？

          神通驱动返回的数据库产品名为 OSCAR，Flowable 无法自动识别。项目会在未设置 flowable.database-type 时，将其按 oracle 处理，使用 Flowable 内置的 Oracle 建表脚本（BLOB、CLOB 字段及大写的表名）。如果显式设置了 flowable.database-type，以显式设置为准，神通需要设置为 oracle，不要设置为 postgres。

          Flowable 按默认的 flowable.database-schema-update: true，自动创建 Flowable 引擎的 ACT_、FLW_ 表，但不会创建 BPM 模块的 bpm_ 业务表。和其它数据库一样，开启工作流前，需要先按 《工作流 · 功能开启》 获取 BPM 的 SQL，转换为神通可以执行的 SQL（包括 bpm_ 表对应的序列）后导入。只导入 9.2 中的项目 SQL，无法使用工作流的业务功能。

          # 9.4.3 代码生成？

          代码生成可以导入神通中的表。神通会将未加引号的表名、字段名转为大写，生成的类名、字段名与其它数据库一致；表和字段的中文注释、从数据库同步字段都可以使用，text 字段会生成为 String 类型。

          生成的菜单 SQL 与 Oracle、达梦一样使用匿名块，依赖 9.2 中第 ④ 步设置的主键默认值；结尾的 / 是部分客户端使用的块结束符。

          # 9.4.4 验证范围？

          在神通数据库 7.0.14 上，使用 Maven 中央仓库的驱动 4.1.152，基于 master-jdk17 分支完成了验证：按 9.2 全新导入项目 SQL，启动项目并登录，用户、角色分配菜单、租户、站内信、数据源配置等功能的增删改查与分页，代码生成的导入表、预览、下载、同步字段，以及生成的单表代码编译后的增删改查、Excel 导出，生成的菜单 SQL 执行。

          Quartz、工作流同样基于上述环境验证（单机，未验证集群下的故障切换）：

          CREATE USER yudao PASSWORD '数据库密码';
CREATE DATABASE "ruoyi-vue-pro" OWNER yudao ENCODING 'UTF8';

          GRANT USAGE, CREATE ON SCHEMA public TO yudao;

          ③ 使用 yudao 账号，在 ruoyi-vue-pro 数据库中先执行 sql/opengauss/quartz.sql 文件，再执行去掉 dual 段后的 sql/opengauss/ruoyi-vue-pro.sql 文件。

          Vastbase 与 GaussDB 一样已经内置了 dual 视图，不要删除或修改它。去掉 dual 段，可以使用如下命令生成新文件：

          sed '/^-- Table structure for dual$/,/^-- @formatter:on$/d' sql/opengauss/ruoyi-vue-pro.sql > ruoyi-vue-pro-without-dual.sql

          # 10.3 如何启动项目？

          ① 在 yudao-server/pom.xml 中引入 Vastbase 的 JDBC 驱动（p 版，驱动类为 org.postgresql.Driver）：

          <dependency>
    <groupId>cn.com.vastdata</groupId>
    <artifactId>vastbase-jdbc</artifactId>
    <version>2.16p</version>
</dependency>

          注意，p 版驱动与 PostgreSQL 官方驱动 org.postgresql:postgresql 的包名、类名相同，两者只能引入一个。

          ② 修改 application-local.yaml 配置文件，将数据库的 url、username、password 修改为 Vastbase 数据库。例如说：

          spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:postgresql://127.0.0.1:5432/ruoyi-vue-pro
          driver-class-name: org.postgresql.Driver
          username: yudao
          password: ${VASTBASE_PASSWORD}

          端口以安装时的设置为准。

          疑问：为什么 jdbc 使用 postgres 数据库连接？

          因为 PG 兼容模式下，Vastbase 的 p 版驱动使用 jdbc:postgresql: 的 url，返回的数据库产品名也是 PostgreSQL，所以项目按 PostgreSQL 处理主键、Quartz、代码生成，Flowable 也自动识别为 PostgreSQL，无需额外配置。

          Vastbase 的 v 版驱动（cn.com.vastbase.Driver，jdbc:vastbase:）可以连接，但项目不会将 jdbc:vastbase: 识别为 PostgreSQL，请使用 p 版驱动。

          可以使用 Linux 或 Docker 等多种方式。

          在项目 sql/tools 目录下运行：

          docker compose up -d mogdb

          注意，mogdb 服务属于 mogdb profile，执行 docker compose up -d 时不会启动，需要像上面一样指定服务名。端口只绑定本机 127.0.0.1:15432，omm、mogdb 用户的密码为 docker-compose.yaml 中的 GS_PASSWORD。

          # 11.2 如何导入数据？

          MogDB 默认创建的是 A（Oracle）兼容模式的数据库，varchar(n) 按字节计算长度，导入项目脚本时会在中文数据处报 value too long for type character varying(32) 错误，所以需要使用 PG 兼容模式、UTF8 编码的数据库。

          有手动导入、Docker 一键导入两种方式，任选其一即可，不要混用。

          ① 手动导入：使用 gsql 等工具，执行如下 SQL 创建数据库（mogdb 为项目连接使用的账号）：

          CREATE DATABASE "ruoyi-vue-pro" OWNER mogdb ENCODING 'UTF8' DBCOMPATIBILITY = 'PG';

          使用 mogdb 账号，在该数据库中先执行 sql/opengauss/quartz.sql 文件，再执行 sql/opengauss/ruoyi-vue-pro.sql 文件。

          ② Docker 一键导入：在项目 sql/tools 目录下运行，自动创建上述数据库并导入 SQL 文件：

          docker compose exec -u omm mogdb bash /tmp/create_schema.sh

          注意，导入脚本只允许创建全新的数据库，数据库已存在（包括空库）或重复执行时，会拒绝导入并返回失败；导入失败时会保留数据库，便于排查。如需重新初始化，执行 docker compose down mogdb 后，删除 ruoyi-vue-pro_mogdb 数据卷。

          # 11.3 如何启动项目？

          ① 在 yudao-server/pom.xml 中引入 openGauss JDBC 驱动，版本由 yudao-dependencies 统一管理（7.0.0-og），无需填写：

          <dependency>
    <groupId>org.opengauss</groupId>
    <artifactId>opengauss-jdbc</artifactId>
</dependency>

          yudao-spring-boot-starter-mybatis 中的 opengauss-jdbc 依赖是 <optional>true</optional>，不会传递到 yudao-server，所以需要在 yudao-server 中引入。

          也可以使用云和恩墨发布的 io.mogdb:opengauss-jdbc:5.0.1-og 驱动，两者的驱动类名相同，只能引入一个。

          ② 修改 application-local.yaml 配置文件，将数据库的 url、username、password 修改为 MogDB 数据库。例如说：

          spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:opengauss://127.0.0.1:15432/ruoyi-vue-pro
          driver-class-name: org.opengauss.Driver
          username: mogdb
          password: Yudao@2024

          omm 初始用户不允许远程连接，项目使用 mogdb 用户。validation-query 保持默认的 SELECT 1 FROM DUAL 即可，sql/opengauss 脚本会创建 dual 表。

          疑问：项目是如何适配 MogDB 的？

          项目会将 jdbc:opengauss: 的 url 识别为 PostgreSQL，自动使用 INPUT 主键（配合 SQL 脚本中的序列），并将 Quartz 设置为 PostgreSQLDelegate；代码生成器也按 PostgreSQL 生成菜单 SQL。

          7.0.0-og 驱动返回的数据库产品名是 openGauss，5.0.1-og 驱动返回的是 PostgreSQL，项目都会识别。

          注意，目前只有 master-jdk17 分支包含该识别处理。

          ③ 后续启动项目，就可以了。

          # 12.3.1 空 pending 报错？

          TongRDS 2.2.1.3 在消费组没有待处理消息时，XPENDING 返回 RESP 错误 -null，导致 opsForStream().pending() 抛出 InvalidDataAccessApiUsageException，影响项目的待处理消息重发任务。

          可以在 yudao-server 模块的 cn.iocoder.yudao.server.config 包中增加如下连接工厂，只兼容该特定响应。非空摘要继续使用原 Redisson 实现；异常响应还需要通过原始 XINFO GROUPS 确认消费组存在、待处理数量确实为零。

          友情提示

          下面的代码在 Redisson 4.7.0、redisson-spring-data-35 上验证通过，用于处理 TongRDS 2.2.1.3 的空 pending 响应。

          查看完整兼容代码 
          package cn.iocoder.yudao.server.config;

import org.redisson.api.RedissonClient;
import org.redisson.client.RedisException;
import org.redisson.client.codec.StringCodec;
import org.redisson.client.protocol.RedisCommand;
import org.redisson.client.protocol.decoder.ListMultiDecoder2;
import org.redisson.client.protocol.decoder.ObjectListReplayDecoder;
import org.redisson.spring.data.connection.RedissonConnection;
import org.redisson.spring.data.connection.RedissonConnectionFactory;
import org.redisson.spring.data.connection.RedissonStreamCommands;
import org.springframework.dao.DataAccessException;
import org.springframework.data.redis.connection.RedisConnection;
import org.springframework.data.redis.connection.RedisStreamCommands;
import org.springframework.data.redis.connection.stream.PendingMessagesSummary;

import java.util.Collections;
import java.util.List;

public class TongRdsConnectionFactory extends RedissonConnectionFactory {

    private final RedissonClient client;

    public TongRdsConnectionFactory(RedissonClient client) {
        super(client);
        this.client = client;
    }

    @Override
    public RedisConnection getConnection() {
        return new RedissonConnection(client, isFilterOkResponses()) {
            @Override
            public RedisStreamCommands streamCommands() {
                return new RedissonStreamCommands(this, redisson.getCommandExecutor()) {
                    @Override
                    public PendingMessagesSummary xPending(byte[] key, String groupName) {
                        try {
                            return super.xPending(key, groupName);
                        } catch (DataAccessException ex) {
                            Throwable cause = ex.getMostSpecificCause();
                            if (!(cause instanceof RedisException) || cause.getMessage() == null
                                    || !cause.getMessage().startsWith("null. channel:")) {
                                throw ex;
                            }
                            List<List<Object>> groups = sync(redisson.getCommandExecutor().readAsync(key,
                                    StringCodec.INSTANCE, new RedisCommand<List<List<Object>>>("XINFO", "GROUPS",
                                    new ListMultiDecoder2(new ObjectListReplayDecoder<>(), new ObjectListReplayDecoder<>())), key));
                            boolean empty = groups.stream().anyMatch(group -> isEmptyGroup(group, groupName));
                            if (!empty) {
                                throw ex;
                            }
                            return new PendingMessagesSummary(groupName, 0,
                                    org.springframework.data.domain.Range.unbounded(), Collections.emptyMap());
                        }
                    }
                };
            }
        };
    }

    private static boolean isEmptyGroup(List<Object> fields, String groupName) {
        String name = null;
        Long pending = null;
        for (int i = 0; i + 1 < fields.size(); i += 2) {
            if ("name".equals(fields.get(i))) {
                name = fields.get(i + 1).toString();
            } else if ("pending".equals(fields.get(i))) {
                pending = Long.valueOf(fields.get(i + 1).toString());
            }
        }
        return groupName.equals(name) && Long.valueOf(0).equals(pending);
    }
}

          再增加 TongRdsConfiguration 配置类：

          package cn.iocoder.yudao.server.config;

import org.redisson.api.RedissonClient;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
@ConditionalOnProperty(name = "yudao.tongrds.enabled", havingValue = "true")
public class TongRdsConfiguration {

    @Bean
    public TongRdsConnectionFactory redisConnectionFactory(RedissonClient client) {
        return new TongRdsConnectionFactory(client);
    }
}

          最后，在对应环境的配置文件中启用：

          yudao:
  tongrds:
    enabled: true

          # 13.3 常见问题？

          # 13.3.1 如何验证 Redis 兼容性？

          CacheDB 宣称兼容 Redis 协议，但项目能启动、能登录、能看到缓存数据，并不能证明 Redisson、Lua、Stream、发布订阅等能力完全兼容。例如说，东方通 TongRDS 就出现过空 pending 报错，可见 《12.3.1 空 pending 报错？》。

          项目使用到的 Redis 能力如下：

          能力 主要命令 项目中的使用
          基础读写、过期 GET、SET、SET NX EX、DEL、EXPIRE 缓存、登录令牌、幂等、API 签名
          游标扫描 SCAN Spring Cache 按前缀批量清理缓存
          Lua 脚本 EVAL、EVALSHA Redisson 分布式锁、@RateLimiter 限流
          发布订阅 PUBLISH、SUBSCRIBE Redisson 锁释放通知、Redis 广播消息（例如说 WebSocket 的 redis 发送方式）
          Stream XADD、XGROUP、XREADGROUP、XACK、XPENDING、XRANGE、XTRIM Redis MQ 集群消费、待处理消息重发、过期消息清理
          服务信息 INFO 存在 Redis Stream 消费者时，启动校验 redis_version 不低于 5.0

          启动项目前，可以先使用 redis-cli 逐项验证。以下命令中的地址 127.0.0.1、端口 6379 和密码，需要替换为 CacheDB 实例的实际值：

          export REDISCLI_AUTH='CacheDB 密码'

redis-cli -h 127.0.0.1 -p 6379 PING
redis-cli -h 127.0.0.1 -p 6379 INFO server | grep redis_version
redis-cli -h 127.0.0.1 -p 6379 SET yudao:bes:test 1 NX EX 60
redis-cli -h 127.0.0.1 -p 6379 SCAN 0 MATCH 'yudao:bes:*' COUNT 100
redis-cli -h 127.0.0.1 -p 6379 EVAL "return redis.call('GET', KEYS[1])" 1 yudao:bes:test

redis-cli -h 127.0.0.1 -p 6379 XGROUP CREATE yudao:bes:stream g1 0 MKSTREAM
MSG_ID=$(redis-cli -h 127.0.0.1 -p 6379 XADD yudao:bes:stream '*' k v)
redis-cli -h 127.0.0.1 -p 6379 XREADGROUP GROUP g1 c1 COUNT 1 STREAMS yudao:bes:stream '>'
redis-cli -h 127.0.0.1 -p 6379 XPENDING yudao:bes:stream g1
redis-cli -h 127.0.0.1 -p 6379 XRANGE yudao:bes:stream - +
redis-cli -h 127.0.0.1 -p 6379 XACK yudao:bes:stream g1 "$MSG_ID"
redis-cli -h 127.0.0.1 -p 6379 XPENDING yudao:bes:stream g1
redis-cli -h 127.0.0.1 -p 6379 XTRIM yudao:bes:stream MAXLEN 0

redis-cli -h 127.0.0.1 -p 6379 DEL yudao:bes:test yudao:bes:stream

          注意，最后一次 XPENDING 是在没有待处理消息时执行的，也需要正常返回 0，不能报错。

          发布订阅需要开两个终端验证，每个终端都需要单独设置密码。第一个终端执行订阅：

          export REDISCLI_AUTH='CacheDB 密码'
redis-cli -h 127.0.0.1 -p 6379 SUBSCRIBE yudao:bes:channel

          第二个终端执行发布，确认第一个终端收到 hello 消息：

          export REDISCLI_AUTH='CacheDB 密码'
redis-cli -h 127.0.0.1 -p 6379 PUBLISH yudao:bes:channel hello

          以上命令都通过后，再启动项目，验证登录、缓存清理、分布式锁、限流，以及你启用的 Redis MQ、WebSocket 等功能。
